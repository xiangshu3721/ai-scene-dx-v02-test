# AI场景诊断 V0.2 现有问题清单

审计基线：测试仓 `xiangshu3721/ai-scene-dx-v02-test` 的 `main` @ `33b2214`（报告页首段留白调整）。正式仓 `ai-scene-dx` 未改。对照文件：`js/v2-data.js`、`js/v2-engine.js`、`js/v2-ui.js`、`js/app.js`、`js/config.js`、`js/consult-config.js`、`server/cloudbase/index.js`、`server/ai-proxy.js`、`server/cloudbase/v2-engine.js`（与前端引擎内容相同）。

结论先说：问卷能跑完，报告能存，微信会诊入口是真的（`xiangshu-pm` + `img/wechat-qr.png`）。但「困难选择」被当成了推荐顺序，TOP3 会按模板凑满 3 个，前后对比和微体验都钉在第 1 条上，微体验是与场景无关的固定演示。

## 1. 问卷与答案结构

7 题，顺序写在 `js/v2-ui.js` 的 `STEPS`：身份 `status`、目标 `goals`（最多 3）、场景 `scenes`（最多 4）、困难 `pains`、频率+影响 `impact`、自定义 `custom`、一个月期望 `month`。题目文案和选项在 `js/v2-data.js`。

已有且应保留的行为：

- 「还不清楚，想看看AI能做什么」与其他目标互斥（`GOALS` 的 `exclusive`）。
- 「暂时没有明显困难」与其他困难互斥（`PAINS` 的 `exclusive`，`toggle()` 会清掉其余项）。
- 选了「没有明显困难」会跳过频率/影响题。
- 发给模型的是匿名作答，不含姓名、电话、微信。

问题：

| 问题 | 代码事实 |
|---|---|
| 多选被强制分出「最优先」 | 困难题文案要求点「最优先」。多选时渲染 `☆ 设为最优先` / `★ 最优先`（`data-act="v2PainTop"`）。`canNext()` 在困难题要求 `painTop` 非空，不标就不能下一步。 |
| 只选一项会自动星标 | `v2Pain`：只剩 1 项时 `painTop = arr[0]`。`v2Scene` 改场景后，若剩余困难只剩 1 个，同样自动写入 `painTop`。 |
| 原始答案带有隐含优先级 | 答案对象含 `painTop`。`anon()` 会把它发给 `/followup` 和 `/report`。`promptInput()` 单独给模型一个字段「最头疼」。 |
| 点击顺序会进入排序 | `toggle()` 用 `push`，数组顺序就是点击顺序。规则引擎在没有 `painTop` 命中时用 `chosen[0]`（场景数组第一项）当头号场景。目标也用 `(a.goals \|\| [])[0]` 映射场景。 |
| 频率/影响被说成某一件「最头疼的事」 | 第 5 题标题是「『{painTop 标签}』这件事，影响有多大？」。多项困难里，只有被星标的那项进入强度判断。 |

困难选择因此不等于「用户觉得烦的几件事」，而等于「请用户替 AI 排落地顺序」。

## 2. DeepSeek 接入与提示词

服务端只有两条生成路径，都在 `server/cloudbase/index.js`（`server/ai-proxy.js` 是同一逻辑的另一份）：

- `POST /followup`：一次调用，系统提示词 `SYS_FOLLOW`。只决定要不要再问 1 道单选题。
- `POST /report`：一次调用，系统提示词 `SYS_REPORT`。直接要 3 个机会 + 只针对「第一个」的前后对比。

密钥只读环境变量 `DEEPSEEK_API_KEY`，健康检查只返回 `ai: true/false`，错误体是 `{ error: "ai_unavailable" }`，不回传密钥。这一点是对的，V0.3 保持。

问题：

- 没有「先理解、再评估、再写给用户」的分阶段。一次生成里，事实、推断、排序和文案缠在一起。
- 提示词要求「至少凑满方向」，并写明「第一个机会是重点」，没有五维评分、门槛、去重和「可以少于 3 个」。
- 提示词把「最头疼的事」当成优先信号，和「困难是并列的」相反。
- 没有单独的微体验接口。前端的演示不经过 DeepSeek。
- 前端 `/report` 超时写死 25 秒（`v2-ui.js` 的 `generate()`）。分阶段多次调用必须放宽超时，并仍短于云函数 60 秒上限。
- `js/v2-engine.js` 与 `server/cloudbase/v2-engine.js` 是两份拷贝，改一处漏一处就会让本地规则和线上校验不一致。

## 3. TOP3 是否依赖固定模板或选择顺序

依赖，而且规则引擎和模型校验两头都依赖。

规则引擎 `localReport()`（`js/v2-engine.js`）：

1. 用 `painTop` 在已选场景里找第一个 `scene.pains` 包含该困难的场景，作为 `primary`。
2. 找不到就用已选场景数组的第 1 个；再没有就用 `GOAL_SCENE[第一个目标]`。`biz`（赚钱/获客）被固定映射到 `comm`。
3. 机会文案、前后对比、微体验类型全部来自 `SCENES[].opp` 固定模板。
4. 循环补到 3 条；若 3 条都来自用户选择，还会把第 3 条换成「主动发现」。这是凑数。
5. 自定义需求只是拼进第 1 条的 `why`，不会单独成为一个场景，也不会阻止跑题。

模型结果 `validateReport()`：

- 只收前 3 条，字段不全就丢。
- 若不够 3 条，用规则模板补齐。
- 若没有 `source:"user"`，把规则引擎的第 1 条插到最前。规则引擎那条仍然可能来自 `painTop` 或点击顺序。
- 前后对比只保留一份，挂在整份报告的 `flow` 上，不挂在某个 `scenario_id` 上。

因此：即使用了 DeepSeek，排序仍可能被本地 `painTop` 改写，条数仍会被模板补满。

## 4. 排序实际逻辑（用户看到的）

用户看到的顺序就是 `opps` 数组下标。第 1 条加「重点推荐」，不是因为五维评估更高，而是因为它排在下标 0。

没有可解释的优先理由字段。规则文案会写「你说最头疼的是……」，把星标直接说成排序依据。

页面不展示百分制，这点符合「不要假百分制」。但内部也没有可复核的分项，失败时无法说明为什么是这个顺序。

刷新：报告写入 `localStorage`（`asdx.reports.v1`）后，再次打开不会重算。不稳定发生在「每次重新生成」：模型温度 0.4，且规则补位依赖 `painTop` 和数组顺序。V0.3 仍要保证同一次成功结果重开不变。

## 5. 前后对比

- 规则版：`scene(primary).opp.before/after`，只生成一份。
- 模型版：提示词要求 `flow` 只针对第一个机会。
- 渲染：`v2-ui.js` 读 `r.flow`，不读机会上的场景编号。
- 没有「点另一张机会卡就换对比」的状态。`active` 与 `recommended` 没有分开。

所以对比图永远跟着数组第 1 项，不能跟着用户正在看的场景。

## 6. 微体验

`v2-ui.js` 的 `DEMOS` / `DEMO_TXT` 是四段写死的对话：

- `table`：三款扫地机器人对比
- `plan`：一个月学做 PPT
- `draft`：小店朋友圈
- `reply`：客户催货/议价

渲染标题是「AI 微体验」加标签「演示」，并写明「数据是虚构的」。`demo.type` 只由头号场景的 `scene.demo` 决定（`table|plan|draft|reply`）。

后果：用户选「整理文档、表格」，只要模板类型同为 `table`，就会看到扫地机器人。这和资料整理无关，也不能按 `scenario_id` 重试，更没有「这次失败了」和「别的场景的结果」之间的隔离。

## 7. 报告存储与微信会诊

存储（`js/app.js` + `v2-ui.js` 的 `save()`）：

- 键 `asdx.reports.v1`，最多 20 条。V0.2 记录 `v: 2`，答案放在 `a`，故意不写旧版的 `answers`，避免同域旧页面误渲染。
- 列表过滤只认 `v === 2` 或旧版 `profile + answers`。新记录若用 `v: 3`，必须同时放行，否则「我的报告」会丢。
- `openRec()` 只有 `v === 2` 才进 `report2`。
- 旧报告没有 `top_opportunities` 时，必须仍能打开，不能现场编造五维分数或证据。

会诊（`js/consult-config.js`）：

- 顾问名「翔叔」，微信号 `xiangshu-pm`，二维码 `img/wechat-qr.png`。两者都空时显示「联系方式待配置」，不给一个点了没反应的按钮。
- 报告区已有「免费，约 45 分钟」和《AI行动建议卡》四项。按钮文案是「预约免费45分钟会诊」。
- 没有编造微信号。V0.3 不得改掉这个配置，也不得在代码里写死另一个号。

降级：端点为空、超时、非 2xx、坏 JSON 时，`generate()` 走 `localReport()`。页面不会白屏。文案是「本报告由本地规则生成（简化版）」，还不是「基础初诊」，而且内容仍是凑满 3 条的模板。
