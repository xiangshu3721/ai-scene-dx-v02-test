# AI场景诊断 V0.3 修改方案

范围：只改测试仓 `ai-scene-dx-v02-test`。正式仓与正式站不动。在现有 H5 和 `asdxAiProxy` 上增量改，不重做首页。

产品顺序：测 → 诊 → 看 → 体验 → 聊 → 做。P0 做诊断、可解释的 TOP≤3、当前场景前后对比、绑定场景的微体验、免费 45 分钟会诊。不做支付、日历、社群、复杂评分展示、多个独立 Agent。

## 2. 答案：取消人工优先级

困难题改为「可以多选，几项同等重要，不用分先后」。删除「设为最优先」、自动星标、以及「不选最优先就不能下一步」。

「暂时没有明显困难」仍与其他选项互斥。目标里的「还不清楚」同样互斥。

原始答案在进入规则引擎和模型之前做 `normalizeAnswer`：

- 删除 `painTop`，提示词里也不再出现「最头疼」。
- `goals` / `scenes` / `pains` 按题库定义顺序重排，不保留点击顺序。
- 互斥项若和别的项同时出现，只留互斥项。
- 选了「没有明显困难」时，频率和影响清空，不拿它们给某个困难加权。

频率/影响改成问「这些并列的困难整体上怎么样」。只选了一项时可以点名该项，但不叫它最优先。

困难集合只描述「哪里不顺」，不决定推荐落地顺序。顺序只来自第 2 阶段的评估。

## 3. 数据结构


## 4. DeepSeek：同一模型，分三次

人设（三段和微体验共用）：

> 你是以真实场景为中心的 AI 应用诊断顾问，不是工具销售员。先理解再推荐；区分事实与推断；兼顾减负、增能、创造；不凑数；不虚构效果；缺信息标待确认；优先可小规模验证；用通俗中文。微体验必须匹配选定场景。

阶段 1，需求理解。输入规范化问卷。输出 `facts / inferred / unknowns / sensitive`。禁止把推断当事实，禁止根据职业编工作内容，禁止从选项顺序猜优先级。服务端再用问卷生成一组「硬事实」；模型若把获客写成事实、但用户原话和已选场景都不支持，这条从 facts 去掉，放进 inferred 或直接丢弃。

阶段 2，候选场景 + 五维评估。每个候选 0–5 整数：

| 维度 | 权重 | 含义 |
|---|---|---|
| match | 30% | 和用户明确场景、原话是否是同一件事 |
| intensity | 25% | 发生得有多勤、影响大不大；无痛点时必须低 |
| value | 20% | 对用户声明的目标有没有帮助 |
| feasibility | 15% | 现有通用模型能不能做这一小步 |
| landing | 10% | 分高 = 更容易先做小规模验证 |

服务端计算 `weighted`（0–5 的加权，不换算成百分数，也不展示百分数）。然后：

- 同一 `scenario_id` 只留分高的一条。
- `organize` 与 `routine` 视为近义（都是把零散记录收成表），只留一条。用户两张都选时仍只留评估更高的那条，避免同一件「汇总表」出现两张卡。
- 门槛：`match < 2` 或 `weighted < 2` 丢弃。无明确困难且没有具体原话时不放行。无痛点时最多留 1 条，并写成「可以小试，不是紧急问题」。
- 风险：健康、法律、财务、隐私只保留人机协作，不提高可行性来凑分。
- 获客校验：标题或证据出现「获客 / 引流 / 拓客」，但用户原话没有这些意思、也没选沟通场景，整条丢弃。仅仅勾了「帮助做生意、赚钱、获客」不算证据。
- 资料整理校验：用户选了整理或原话明显是整理/表格/纪要时，若模型把该场景的 match 打得过低，用规则分兜住 match，避免跑成文案或获客。
- 通过的按 `weighted` 降序、`scenario_id` 升序，取最多 3 条。不够不补。

阶段 3，只给已经定序的场景写用户文字：洞察、机会卡、优先理由、AI/人分工、该场景的前后对比、微体验配置、会诊待确认问题。服务端按阶段 2 的 `scenario_id` 名单合并。阶段 3 不得新增场景、不得改排名。它如果把 `recommended_scenario_id` 写成别人，服务端忽略，仍用名单第 1 个。

任一阶段请求失败，或阶段 2 没有可用候选：整份改为规则库结果，`source: "rules"`，页面标「基础初诊」。阶段 3 单独失败时，保留阶段 2 的场景和分数，文案用模板补上，仍标记为 AI 诊断（场景不是凑的）。完全失败时报告页和会诊照常渲染。

`/followup` 仍最多 1 题，且不得追问「哪个最优先」。

温度 0.3。超时大约：理解 12 秒、发现 16 秒、成稿 18 秒，合计低于云函数 60 秒。前端等待报告约 52 秒，失败再走本地规则。

## 5. 规则库（基础初诊）怎么打分

不再读 `painTop`，不再读数组第 1 项。每个带模板的场景用同一套五维，全部来自可核对的答案：

- match：选了该场景 +3；原话命中该场景关键词 +2；目标方向一致 +1（`biz → 沟通` 不算，除非原话或已选场景支持）；困难与该场景的困难集合重叠且场景已被选中或被原话命中 +1。封顶 5。
- intensity：由频率和影响相加。无痛点时最高 1。
- value：一个月期望若落在该场景 +2，目标方向一致 +1。
- feasibility：整理/重复类较高，决策/管理类较低；敏感内容再压低。
- landing：有对得上的原话更高；只是「发现」而用户没选、也没写到，最高 2。

门槛、去重、无痛点上限与阶段 2 相同。自定义原话写进该机会的 evidence，不写进无关场景。

## 6. 报告页状态

顺序：洞察（规则结果带「基础初诊」）→ 已确认 / 还要确认（推断不放进已确认）→ TOP 卡 → 当前场景前后对比 → 当前场景微体验 → 会诊。

TOP 卡可点。点击只调用 `setActiveScenario`，改 `active_scenario_id`，不改 `top_opportunities` 的顺序和 `recommended_scenario_id`。排名第 1 保持「建议先做」。正在看的其他卡只标「当前查看」。对比和微体验区的 `data-scenario` 必须等于当前 `active_scenario_id`。

结果写回 `localStorage` 里同一条报告。刷新、从「我的报告」进入，排名和当前场景都保持。

没有过门槛的场景时不渲染空卡，说明这次不强行推荐，会诊入口仍在。

## 7. 微体验

`POST /micro`，正文：`scenario_id`、该机会的标题和任务、用户补充的一小段材料。材料至少几个字，否则不请求。

模型只许返回这个 `scenario_id` 的小成果（纯文本）和下一步建议。校验函数若发现编号不一致，整段丢弃。前端用请求序号：后返回的旧请求不能覆盖新场景；结果只写入 `microByScenario[请求的 scenario_id]`。失败时该场景显示「没生成成功，可以重试」，不把别的场景的成果或静态样例填进结果区。

静态样例可以出现在结果区外面，标题带「示例」，内容来自该 `scenario_id` 的 `sample`。未配置端点或云函数还没有 `/micro` 时，报告其余部分可用，微体验说明「现在不能生成实时结果」。

密钥只出现在云函数环境变量。响应和前端脚本不含密钥、不含 `api.deepseek.com`。

## 8. 会诊

继续读 `js/consult-config.js`。不在逻辑里写死微信号。文案保持：免费 45 分钟、微信、翔叔、《AI行动建议卡》（3 个以内的机会、优先做的 1 个、实现思路、下一步）。当前场景的 `consult_questions` 显示为「会诊时可以先确认」。45 分钟不承诺做完开发。

## 9. 验收对照（PRD A–K）

| 编号 | 标准 | 怎么测 |
|---|---|---|
| A | 多选没有最优先，答案无隐含优先级 | 单测：正反点击顺序的困难/场景，推荐名单一致；页面无「设为最优先」。困难题选「没有明显困难」会清掉其他项。 |
| B | 获客不武断 | 只勾「赚钱、获客」、原话是比较供应商：推荐不是获客场景，facts 不出现「你有获客问题」。阶段 2 若给获客卡且无原话支持，会被丢掉。 |
| C | 资料整理不跑题 | 选整理 + 原话写纪要/表格：`recommended_scenario_id` 为 `organize`，微体验任务含整理，不含扫地/机器人。 |
| D | 排序可解释 | 每条有 `priority_reason` 和五维分；理由不含百分号；名次等于评估顺序，不是点击顺序。 |
| E | 去重 | 同一 `scenario_id` 两条合并；整理 + 重复且都在说汇总表时只留一条。 |
| F | 微体验强关联 | `micro.scenario_id ===` 该机会的 `scenario_id`。`/micro` 返回别的编号则校验失败。 |
| G | 切换同步且不改排名 | `setActiveScenario` 后推荐 id 和数组顺序不变，对比/微体验区的 `data-scenario` 变成当前 id。 |
| H | 特殊需求 | 原话「民宿房态和客人偏好」出现在 facts 或该机会 evidence，并落到整理或 custom，而不是被丢掉。 |
| I | 无痛点不强行 | 身份普通、目标不清楚、场景「其他」、困难「没有」：机会 ≤ 1，文案不说最优先、不说紧急。 |
| J | 会诊入口 | 默认配置可见免费 45 分钟、`xiangshu-pm`、二维码、行动建议卡。配置被清空时显示「待配置」而不是坏按钮。 |
| K | 失败不崩、不串、密钥不出现 | 阶段调用抛错得到 `source:"rules"` 的基础初诊。微体验错场景被拒。仓库与响应无密钥。端点 500 时报告页仍出现会诊。 |
